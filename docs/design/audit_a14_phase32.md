# Audit A14, phase 32: code, tests and documents

Issues: MT14-2, CB14-1, CB14-2, IB14-1, IB14-5, SW14-1, and the scope statement of the band-unit table (the closed
findings IB14-2 to IB14-4). Base: code soil-zone 32a3857, extra 61fcccd. Reference build: wt/rel30_Raven.exe.

## MT14-2: E40 sees the shift of a copied-in series

E40 used q1 on the first `3 63 76 -3.0E+03` row, in period 2, which the late start (32 days) drops; the working copy did
not use the series at all, so an unshifted copy passed. Now `outside()` puts q1 on the period-3 row (the first period the
late start keeps) and writes a series of its own (`TS40`: -1000 to day 32, -20000 from day 34). The late case also checks
that the copied file (`raven_copy_f<n>_wel.ts`) carries Raven's shift line and begins at -32. Sensitivity (probe in
wt/p32/probe/probe.py): with the outside series pre-shifted by +32 days, which is what an unshifted copy of the written
series gives, GWBudget.csv and Hydrographs.csv differ from the twin's; as written they are identical (rel30 and this build).

## CB14-1: the two unreachable TS6 stops

`ExtLocalizePaths` runs before `ExtRenumberPeriods` and names every TS6 FILEIN of the kept packages by a path inside the
working copy (an existing file outside the folder copied in as `raven_copy_f<n>_*`, an absolute path inside the folder
made relative, an outside OPEN/CLOSE file of OPTIONS copied in as `raven_copy_o<n>_*`). The branch for an absolute or
leaving path after it, with its two stops ("outside the simulation folder", "a path Raven cannot rewrite") and the
rewrite of the TS6 line, could be reached only by a file that does not exist, which the existence stop names first. The
branch is removed; the series is shifted where the localized name points. Appendix rows and the user-guide messages for
the two stops are removed. No behaviour change: the existing tests E37, E40, E41d pass on both builds.

## CB14-2: other water models get the one-model message

Only GWT6, GWE6 and PRT6 go into the transport list. Any other model type (CHF6, OLF6, a second GWF6) reaches the
one-model/exchange message. Test E42b: a CHF6 model joined by a `chf6-gwf6` exchange stops with "holds 2 models
(gwf_liard (GWF6), chf1 (CHF6)) and 1 exchange (chf6-gwf6 chf.exg); Raven couples one ...", without the transport
wording. rel30: the transport message (FAIL); this build: PASS.

## IB14-1: a geoid model word is dropped only when it is one

`BUDatum` drops the last word after a datum only when it is `geoid`, or `geoid` followed by exactly 2 or 4 digits and an
optional letter a or b (`geoid90`, `geoid99`, `geoid03`, `geoid12b`, `geoid18`, `geoid2022`), with or without one pair of
brackets (the text is already in lower case). `geoidft`, `geoid_feet`, `geoid-ft`,
`GEOID12B_in_feet`, `geoid/100`, `geoid12b/10` and `GEOID*0.1` are no longer stripped. The scaled texts become X (their
number and factor sign are seen); the feet texts become S (they stop; METRES is the user's statement, with the warning
naming the text). The seven texts are rows of band_units.tsv (geotiff_check): with the rel30 source all seven load as
metres (7 FAIL); with this source all pass.

## IB14-5: a # glued to a value in the .rvg

The .rvg keeps base Raven's tokenizer rule (ParseLib.cpp): a `#` starts a comment only at the start of a word, so a value
that holds `#` (a file name such as `hrus#1.geojson`) is read whole. The shared surplus-value check stays; when a value
the command takes holds a `#`, its stop says that a `#` glued to a value is part of it and that a blank must come before
`#` to start a comment. Test E44e: `:MF6StartDate 1985-10-01# the model's time zero` stops with "has the surplus value
'model's' ... a # glued to a value is part of it, as in '1985-10-01#': write a blank before # to start a comment". The
appendix and user-guide rows say: on a command line, a `#` starts a comment only after a blank.

## SW14-1: Workshop 6 per-run time from the same calibration

New value `t6:ddsrunsec`: the time of one DDS run of the recorded calibration, `t6:ddsmin` x 60 / 300 (with --ostrich,
the measured Ostrich time / 300). 07_dds.tex uses it instead of `t6:runsec`, which stays the run time of the build. The
committed tex/generated/values.tex of Workshop 6 holds the line the builder writes (`t6:ddsrunsec` 6, from
`t6:ddsmin` 28; `t6:runsec`, no longer quoted, is not written), so the committed tex compiles; the workshops are
regenerated by the coordinator.

## Band-unit table scope

building.tex (band-unit paragraph) and the user guide state that the table covers the forms it lists, not every
spelling; any other text stops, and METRES is the user's explicit statement that the values are metres, with a warning
naming the text. The geoid-model rule is stated with the datum forms.

   gains `m NAVD88 geoid18ft`, `m NAVD88 GEOID12Bft` and `m NAVD88 geoid1e3` as S. The reviewer's driver (review/scripts/bu.py,

   `m NAVD88 geoid18c` are rows of class S.

   reviewer's `hrus#1.geojson` case runs again, its GWBudget.csv identical to rel30's.

   no claim about the rows of a block, which are read by their own loops.

\section{Validate on 2013--2014}
A calibrated model must also work on data it has not seen.

\step{Make a validation folder}
Copy \cmd{model} to a new folder \cmd{validation}, with the best \cmd{Creek.rvp}:
\begin{shell}
$ cp -r model validation
$ cp best/Creek.rvp validation/
$ cd validation
\end{shell}
If you did not run DDS, there is no \cmd{best}. Use the best \cmd{Creek.rvp} of this workshop instead:
\cmd{cp \$WS/model/finished/best/Creek.rvp validation/} (before \cmd{cd validation}).
Then change \cmd{Creek.rvi}: run the five years 2010--2014, and let Raven score the calibration years and the validation
years separately:
\diff{t6_valid_rvi.diff}

\step{Run the validation}
\term{t6_run_valid.txt}
\term{t6_diag_valid.txt}
\see \cmd{Exiting Gracefully: Successful Simulation}, and in \cmd{Diagnostics.csv} one line per series and period
(\cmd{CALIBRATION} and \cmd{VALIDATION}).
\why the table compares the calibrated set with the initial and the true parameters. The columns \emph{initial} and
\emph{true} are the same validation run with the initial and the true \cmd{Creek.rvp}.

\begin{tocheck}
The calibrated set is much better than the first guess everywhere. It is as good as the true parameters in the validation
years too (KGE \V{t6:kgevalid} against \V{t6:kgevalidtrue}; head errors at the \V{t6:noiseh}-cm noise of the observations
at all three wells), although its sand conductivity is off. Where the observations cannot see a parameter, its error does
no harm to what they measure. It does not help predictions that depend on that parameter either.
\end{tocheck}
